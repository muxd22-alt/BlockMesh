Here is a detailed architectural breakdown of how to build the unified "Decentralized Pi-Hole + Mesh VPN," covering the low-level Go engine and its integration into Android's `VpnService`.

---

## 1. The Go Engine Architecture

The Go engine acts as a "black box" library. The Android/iOS apps know nothing about mesh networking; they simply hand the Go engine a raw network connection (a `tun` interface), and Go handles all the cryptography, peer discovery, and ad-blocking.

You will use `gomobile` to compile this Go code into an `.aar` (Android Archive) library.

### The 4 Pillars of the Go Engine

1. **The WireGuard Userspace Tuner (`wireguard-go`)**
Instead of relying on the Linux kernel, we use the official `wireguard-go` library. It reads raw IP packets from the device's virtual network interface, encrypts them using the WireGuard protocol (ChaCha20-Poly1305), and wraps them in UDP packets.
2. **The P2P Mesh Router (`go-libp2p`)**
Standard WireGuard requires you to hardcode the IP address of your home server. That fails if your home IP changes. `go-libp2p` replaces standard UDP routing. When your phone tries to send a WireGuard packet to your Android TV, `libp2p` finds the TV using a Distributed Hash Table (DHT) and uses STUN/TURN protocols to punch a hole through your home router's firewall, creating a direct P2P connection.
3. **The Local DNS Sinkhole (Ad-Blocker)**
Before a packet goes into the WireGuard tunnel, the Go engine checks if it is a DNS request (Port 53). If it is, the embedded Go DNS server intercepts it. It checks the domain against an in-memory Radix tree of blocked domains (parsed from EasyList).
* *If blocked:* It instantly returns a fake response (e.g., `0.0.0.0`), dropping the ad.
* *If allowed:* It forwards the DNS request through the WireGuard tunnel to a secure resolver (like Cloudflare's `1.1.1.1`).


4. **The FFI Boundary (CGO / Gomobile)**
Go exposes a few simple control functions to the Android app using C-bindings.

### Go Engine Blueprint

```go
// package engine exposed via gomobile bind
package engine

import (
	"golang.zx2c4.com/wireguard/tun"
	"golang.zx2c4.com/wireguard/device"
	"github.com/libp2p/go-libp2p"
)

// StartMesh is called by Kotlin when the user taps "Connect"
func StartMesh(fd int, nodePrivateKey string, peerConfig string) {
    // 1. Take control of the Android TUN file descriptor
    tunDevice, err := tun.CreateTUNFromFile(os.NewFile(uintptr(fd), "/dev/tun"), 1500)
    
    // 2. Initialize the Ad-blocking DNS Interceptor on the TUN
    startLocalDNSSinkhole(tunDevice)

    // 3. Start libp2p host to handle NAT traversal
    host, err := libp2p.New(
        libp2p.NATPortMap(), // Automatically handle UPnP
        libp2p.EnableHolePunching(), 
    )

    // 4. Initialize WireGuard using the TUN device and libp2p UDP transport
    logger := device.NewLogger(device.LogLevelError, "")
    wgDevice := device.NewDevice(tunDevice, buildP2PBind(host), logger)
    
    // 5. Apply WireGuard Configuration
    wgDevice.IpcSet(peerConfig)
}

```

## 2. The Android `VpnService` Implementation

Android's security model strictly forbids apps from capturing device traffic—unless the app holds the `BIND_VPN_SERVICE` permission.

The `VpnService` API allows your app to create a virtual network interface (a TUN device). Android routes all of the phone's internet traffic into this interface. Your Kotlin code grabs the "File Descriptor" (the pipeline) for this interface and hands it over to the compiled Go engine.

### Step 1: Requesting Permission

Before starting, Jetpack Compose must prompt the user to grant VPN permissions. Android will show a system-level warning dialog: "This app wants to set up a VPN connection that allows it to monitor network traffic."

### Step 2: Building the VPN Service (Kotlin)

Once permission is granted, you start your custom `MeshVpnService`. Here is how it establishes the tunnel and passes it to Go:

```kotlin
import android.net.VpnService
import android.os.ParcelFileDescriptor
// 'engine' is the library generated by gomobile
import engine.Engine 

class MeshVpnService : VpnService() {
    
    private var vpnInterface: ParcelFileDescriptor? = null

    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        // 1. Build the Virtual Network Interface (TUN)
        val builder = Builder()
        builder.setSession("Decentralized Pi-Hole")
        
        // Assign a private IP to the phone within the mesh network
        builder.addAddress("10.100.0.2", 32)
        
        // Route ALL traffic through the tunnel (0.0.0.0/0)
        builder.addRoute("0.0.0.0", 0)
        
        // Intercept DNS by telling Android this VPN provides DNS
        builder.addDnsServer("10.100.0.1") 

        // 2. Establish the interface and get the File Descriptor (FD)
        vpnInterface = builder.establish()
        
        // 3. Extract the raw integer FD
        val fd = vpnInterface?.fd ?: return START_NOT_STICKY

        // 4. Detach the FD from Kotlin so Go can take ownership of it
        val rawFd = vpnInterface?.detachFd()!!

        // 5. Pass the FD into the Go Engine asynchronously
        Thread {
            // This calls the Go function we mapped out above!
            Engine.startMesh(rawFd, "private_key_here", "peer_config_string")
        }.start()

        return START_STICKY
    }
    
    override fun onDestroy() {
        vpnInterface?.close()
        Engine.stopMesh() // Tell Go to gracefully shut down libp2p/WireGuard
        super.onDestroy()
    }
}

```

### The Beauty of `detachFd()`

The magic happens at `detachFd()`. In older VPN apps, developers had to write a continuous `while(true)` loop in Java/Kotlin to read bytes from the `vpnInterface`, pass them over JNI to C++, process them, pass them back, and write them back to the interface. This destroyed battery life and caused massive latency.

By using `detachFd()`, you rip the network pipeline completely out of the Java Virtual Machine. You hand the raw file descriptor directly to `wireguard-go`. From that point on, Android's OS kernel communicates directly with your highly optimized Go binary, making the Kotlin app nothing more than a lightweight UI layer.
